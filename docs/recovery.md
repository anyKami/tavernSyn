# 故障与恢复

## 状态含义

只有 `SUCCEEDED` 表示已发布推送，或拉取已应用并通过启动检查。`PENDING_APPLY` 只是下载完成；`RECOVERY_REQUIRED` 要求先检查日志和进程状态。`status.json`、`apply.json`、`baseline.json` 位于设备控制目录，不在镜像中。

## 环境与连接错误

- 缺少 rsync/SSH：Windows 使用同一套 MSYS2 工具，检查 `device.json` 的 `tools`；Termux 安装原生包。
- 主机身份不匹配：首次连接会自动记住服务器身份，变化后拒绝连接。通过可信 VPS 控制台核对后，仅删除设备 `credentials/known_hosts` 中对应地址的旧记录，再检查连接。
- SSH 账号不可登录：确认同步账号密码正确，旧版 VPS 已运行 `vps/enable-password.sh`，并检查 Tailscale 来源及 ACL。专用账号仍禁止交互式 shell，只通过界面检查连接。
- VPS 空数据：先从有完整数据的设备推送。未发布镜像不能拉取。
- 插件依赖失败：查看本机日志，检查网络/npm 路径和目标平台依赖；数据尚未替换。不复制另一系统的 node_modules。
- 保存回执失败：处理酒馆保存错误，完成生成/编辑，清空或保存未发送输入，再尝试。不要把没有回执的快照当成功。

## 网络中断

有效 VPS 镜像不会被未完成上传替换。新版会在控制连接断开且 rsync 进程结束后，将未完成任务暂停并释放占用；上传文件与快照保留，不再因为旧任务记录永久阻止其他任务。进程被强制终止而来不及暂停时，下次操作取得操作锁和传输锁后也会自动暂停旧任务。仍有实际连接或传输进程时继续显示 BUSY，避免同时写入。

推送失败后可直接在扩展面板点击 **继续上次上传**：校验并重用同一份静态快照，不需要再次停止酒馆。也可点击 **推送到 VPS** 创建最新快照；发布基准相同时，VPS 会独立复制或 reflink 旧暂存文件，再补传差异，旧暂存文件仍保留。续传期间不会把新聊天混入旧批次，VPS 已发布其他数据时会拒绝旧快照覆盖。

需要从命令行处理时，记下界面/状态文件的任务 UUID，在控制目录所属设备执行：

```text
node bin/remote-job.mjs --state "D:/TavernSyn-device" --job 任务UUID --action resume
```

推送重用原静态快照，不把恢复连接后产生的新聊天混入原批次。拉取固定原代次，恢复下载后进入待应用；再次从受控入口打开酒馆继续。需要放弃该批次时将 `resume` 改为 `abort`；已发布完成的任务拒绝中止，不撤销当前有效镜像。

VPS 同步账号启用 SSH 存活检查（15 秒、连续 3 次无响应），rsync 无数据活动超时为 120 秒。它们负责清理断开的连接；正在正常传输的大文件不会因任务总时长而被取消。不要靠锁文件时间、PID 猜测或删除当前代次解除保护。客户端与 VPS 都需更新；旧客户端会收到升级提示。

暂停记录位于 VPS `private/paused-jobs/`，上传内容仍在 `incoming/任务UUID/`。暂停的拉取会保留其固定代次，避免被代次回收误删。暂存不会自动删除；不再需要时可明确中止对应任务回收空间，已发布数据不受影响。每条新版 rsync 连接都绑定任务 UUID，迟到的旧连接不能写入新任务目录。

## 未受控启动

通过原 Start.bat、其他面板或外部进程管理器启动的实例不被接管。可以拉取并校验，但停留 `PENDING_APPLY`。正常关闭原实例，改用 TavernSyn 入口，打开本机酒馆页面后继续确认、保存和应用。严格推送需要受控启动。

## 异常退出留下锁

关闭 TavernSyn 启动终端或按 Ctrl+C 会停止所属酒馆；即使浏览器中断过请求也会退出。正常先运行酒馆清理，清理卡住时有退出时限。同步替换期间仍要求严格排空；关窗中断的任务保留 journal，不能把它当作同步成功。

再次启动会自动检查端口和锁中的 PID，清理确认已死进程留下的锁，并恢复未完成的替换。端口被占用或锁中的进程仍存在时仍拒绝接管。需要单独运行恢复工具时，先确认酒馆和助手均已退出：

```text
node bin/recover.mjs --state "D:/TavernSyn-device" --acknowledge-stopped yes
```

进程仍存在或 PID 已被复用时会拒绝清理。请先人工核对，不能通过按端口强杀来绕过。再次使用受控入口时，未完成替换会先依 `apply.json` 撤销，再启动旧数据。

`operation.lock` 已清理但任务停在非终态、且没有待撤销的 `apply.json` 时，应保留任务目录。完整推送快照可在扩展面板继续上传；拉取中断可通过 `remote-job.mjs` 恢复为 `PENDING_APPLY`。没有完整清单时重新推送，服务端会暂停已失去连接的旧任务。

## 启动失败与一次恢复副本

更新前数据在控制目录 `recovery/`，原路径与每步替换记录在 `apply.json`。健康失败时先确认新子进程退出，再恢复旧目录并启动；新进程退出不确定时停止自动回滚，保留所有目录。

在酒馆「扩展设置 → TavernSyn」点击 **恢复上一版**，确认覆盖范围后，助手会保存并核对当前内容、关闭所属酒馆进程，恢复到最近一次拉取前的本机数据，再启动并检查。恢复完全在本机进行，不连接或修改 VPS；当前同步插件代码和 SSH 身份保留。生成中、未发送输入或其他活跃标签页仍会阻止恢复。

按钮显示可用副本时间，没有副本或未受控启动时禁用。成功恢复后该次副本失效，下一次同步重新核对覆盖基准；恢复后的启动检查失败时，先确认子进程退出，再尝试回到恢复操作前的数据，并保留原恢复机会。任何一步无法安全完成都会停在 `RECOVERY_REQUIRED`，保留副本和日志。

恢复副本在下一次更新开始时轮换，只保留一次，不是长期备份。`recover.mjs` 是异常锁清理工具，不能代替「恢复上一版」按钮。如果界面不可用，先关闭所有实例，按 journal 的 `live`/`old` 路径核对再手动还原，不能在运行中覆盖。保留 `credentials/`、`device.json` 和日志。

Windows 已实测替换中断和失败回滚；断电后的硬盘/文件系统持久化仍取决于平台，不能把进程中断测试等同断电验收。
