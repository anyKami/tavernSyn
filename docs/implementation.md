# 0.2.0 实现与验证

日期：2026-10-24。适配 SillyTavern 1.19.0，固定 commit `06bde939fb1e9c4c8d8641d810f0a916b5bce127`。

## 实际实现

0.2.0 汇总密码登录、安装目录调整、断线恢复、界面布局与 Windows 启动入口改进。未完成任务与运行锁分开：控制连接断开后，在实际 rsync 锁释放时暂停旧任务，保留暂存内容；下一次任务也能处理没有执行退出清理的旧记录。暂停的下载固定代次并阻止回收，旧上传的发布基准过期时拒绝覆盖。rsync 连接绑定设备与任务 UUID，迟到连接不能接入新任务。SSH 存活检查与 rsync 无活动超时负责回收断开的连接，不按任务总时长取消正常上传。

Windows 启动入口在所属实例通过启动检查后自动用默认浏览器打开本机酒馆，仅首次启动打开，受控同步重启不重复开页面。`--desktop-shortcut` 创建保留酒馆工作目录与图标的桌面快捷方式；已在实际桌面生成并通过该快捷方式启动验证。推送/拉取日志由父启动器持续显示到同一控制台并写入 `sync.log`，记录阶段、任务编号、rsync 文件变更/错误/统计、SSH 控制步骤与 SHA-256 校验结果。进度输出限频，逐文件变更保留，中文输出按 UTF-8 完整解码；日志不输出账号密码或文件正文。

推送失败后增加「继续上次上传」，使用相同任务号及经校验的原快照，不再停机采集；另行推送仍采集最新内容。仅在 begin 成功后记录远端任务所有权，成功后清除旧错误并更新历史与连接绑定基准。Linux 发布对只读文件使用可读描述符执行 fsync，接收文件确保同步账号可读写，避免只读属性阻止完成发布。Windows 上跳过的真实 flock 与只读 fsync 测试需在 VPS 更新时以同步账号执行。

`ui/` 是原生设置面板；`server/index.mjs` 提供继承酒馆认证与 CSRF 的本机管理员接口；`helper/launcher.mjs` 独立持有子进程、任务和 IPC，`bootstrap.mjs` 在导入酒馆前建立请求维护门控及页面代次检查。源码指纹不符时拒绝启动适配。

0.1.2 将连接表单简化为 VPS 地址、账号和密码，移除设备密钥生成及手工服务器公钥登记；数据集由首次成功连接自动读取并固定。通过 OpenSSH ASKPASS 向 SSH/rsync 提供密码，命令行和环境中只传密码文件路径；配置接口仅返回是否已保存。首次自动记录服务器身份，后续身份变化拒绝连接。VPS 增加密码登录初始化及旧版迁移脚本。

配置保存立即供父子进程使用，操作锁阻止并行任务改目标。同步基准绑定服务器、账号和数据集，换目标后重新确认覆盖。推送、拉取、手动恢复都先确认方向；手动恢复复用替换日志和受控停机，失败时尝试返回操作前状态，不修改 VPS。

本机安装入口为 `install.ps1` / `install.sh`，共用 `bin/setup-device.mjs` 安装前后端和运行库，不生成设备密钥。完整代码统一放到酒馆的 `plugins/tavernsyn`，前端界面放到 `public/scripts/extensions/third-party/tavernsyn`；只下载入口脚本时也会克隆到酒馆内，从外部完整仓库安装时复制发布代码。安装前检查端口、锁和待处理任务；重装复用已有设备身份、账号密码、VPS 配置和可用工具。已有源代码需先自行更新。Windows 需要已安装 Node 20+ 和 Git，Termux 通过 `pkg` 补齐依赖。

受控启动器实时转发子进程的标准输出和错误到启动终端，同时写入设备控制目录的 `server.log`；重启前等待旧日志写完，新进程继续向同一终端输出。Windows 入口使用 UTF-8，启动报错时暂停窗口。

受控 HTML 页面忽略旧缓存校验与范围请求，始终返回包含当前 epoch 的完整页面，并移除 ETag、Last-Modified 和范围缓存标记；HEAD 同样禁止缓存。避免 Edge 等浏览器沿用原 Start.bat 或上次启动的 HTML，导致设置读取被旧页面屏障拒绝。普通 JS/CSS 资源继续按酒馆原有规则缓存。

设置通过自己的 nonce 与可访问设置摘要读回确认，当前聊天用解析后消息及元数据摘要核对。页面真正导航到独立等待文档并 ACK 后，拒绝新请求并排空已有响应；中途断连标记为不确定，不按正常完成处理。同步替换时，子进程内部触发本版本 SIGTERM 清理链路，父进程等真正退出，Windows 不使用强杀代替。

明确关闭启动终端与同步停机分开处理：Ctrl+C/SIGHUP 关闭所属生命周期，IPC 断开也会触发子进程退出，不再被不确定请求阻止；先等待在途请求最多 3 秒并执行原生清理，8 秒仍未结束则自行退出，启动器在 10 秒时为所属子进程兜底。关闭中的生命周期禁止再次启动。下次启动复用恢复工具的端口/PID 检查后清理死锁；同步停机仍严格拒绝未排空或不确定请求。

每次启动的 epoch 在 HTML 的 head 最早注入，同源 fetch/XHR 附加它。重启后的旧 API 写入返回 409，BFCache 恢复要求刷新。浏览器直接加载的 script/module/worker 请求不能附加此头，因此允许 Cocktail+ 的只读桥接脚本、Service Worker 和明确列出的五个核心模块通过；其他插件接口与写请求仍受页面代次检查。此适配不改磁盘上的酒馆 HTML，其他第三方代码共存仍需专项验收。

推送：确认保存 → 停机 → 独立快照和精简 Git → 重启 → rsync → 目标 SHA256 校验 → 原子发布。

拉取：固定代次 → rsync 暂存和校验 → 本机准备插件依赖 → 未推送修改/大批删除确认 → 保存与等待页 → 停机 → 保留设备字段 → journal 替换 → 新实例健康检查 → 成功或停机后回滚。

VPS 通过账号专属 SSH Match/ForceCommand 只接受固定入口及有限 JSON 协议，拒绝非 Tailscale 来源、交互式终端和转发。共享密码设备具有相同权限，设备 UUID 仅用于任务归属与恢复。控制会话 operation 独占锁、传输会话 transfer 共享锁，发布前进入 finalizing 再拿 transfer 独占锁。独立副本不硬链接旧代次，保留 current 与 previous 两份。
