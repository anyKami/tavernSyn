## 0.2.3 插件依赖缓存

插件依赖通过命令行固定使用设备控制目录中的 `npm-cache`，覆盖系统和环境中配置的缓存位置。安装器与依赖准备共用预检查，实际验证缓存根目录、下载暂存和日志目录可以写入，拒绝目录联接等不安全路径。缓存不可用时在 npm 启动前停止；候选目录的权限或占用错误给出明确提示，保留已下载内容，不自动重复执行安装脚本。

Windows 全部 91 项测试通过，包含真实 npm 缓存覆盖、异常目录拒绝，以及 PowerShell 首装和重装。实际失败的 `JS-Slash-Runner` 候选目录使用独立缓存完成安装，原始下载再次通过校验；酒馆数据未应用。详见[验证记录](test-results/dependency-cache-windows.json)。Windows 与 Termux 使用同一实现，本次未做新的安卓真机复测。

## 0.2.2 启动前更新与安装入口

Windows / Termux 安装器在酒馆根目录生成独立的 `TavernSyn-Startup.mjs`，两个平台的启动脚本都先调用它。启动检查使用官方仓库的稳定版本标签，只有版本更高才下载，并固定检查到的标签对象；后端、manifest 与前端版本须一致。已安装后端的代码指纹可识别手工改动，原来安装器保留的旧 Git 元数据不会独自阻止已登记版本的升级。

代码与配套前端在同一文件系统暂存，替换前再次确认所属进程和端口已退出。用户数据和连接配置不参与替换。失败恢复原代码；中断保留更新记录，下次启动先恢复。独立入口在同一个 Node 进程中加载受控启动器，保留关闭终端退出酒馆的行为。已有服务仅在私有 epoch 匹配时复用，避免重复启动或误接其他服务。

Termux 安装器识别兼容的 `$HOME/install.sh` 管理工具，更新选项 4，并仅处理已知的登录下载覆盖命令；未知菜单格式保留。重复安装与重复集成不会重复添加代码。自动更新下载的仓库保留 `main` 跟踪配置，后续仍可按文档手动快进更新。本次手机未连接，新的 Android 安装集成仍待真机复测。[启动更新报告](test-results/startup-update-windows.json)。

请求排空现在区分经核验的只读文件、状态查询和 JSON 标签页心跳与其他请求：前者响应被浏览器取消时不再永久阻塞停机；写入及未知插件请求中断仍保留不确定状态。`status.drain` 与失败提示提供数量及固定请求类型，不记录文件名、查询参数或请求内容。真实酒馆回归先中断大文件 `sendFile`，随后完成正常保存、停机、推送及重启；未知插件中断的拒绝停机回归保留。兼容检查同时固定用户文件路由、CSS 与 webpack 中间件源码。

上传结束后若独立的控制 SSH 已断开，客户端最多自动重连两次。重连固定原服务器、账号、主机密钥记录与数据集，只以 `resumeOnly` 认领保留的原任务；任务、代次、发布基准与阶段不符即停止。已发布但丢失回执时幂等核对同一发布结果，不重复传输；权限、完整性与远端更新冲突不会通过重连绕过。真实 OpenSSH / rsync 回归覆盖上传后断连、发布回执丢失及重连时数据集改变。

SSH 控制进程即使没有等待中的请求也会立即记录退出码、信号和存续时间。rsync 结束后统计先写入任务，再校验发布，因此后续失败仍能显示实际协议发送量。面板和独立等待页共用显示函数，单独标注包含远端复用的文件处理量，避免将其百分比误当实际上传进度。

本次 Windows 回归共 86 项通过，真实酒馆隔离检查 23 项通过。已安装修复的本机通过正式启动入口续接真实 VPS 的保留上传：2,807 个文件、488,847,063 字节的快照无需再传文件内容，本次 rsync 发送 103,809 字节、接收 562 字节，逐文件校验与发布成功。随后独立重新登录 SSH 核对当前发布摘要与原快照一致，酒馆保持运行。此记录是上次已冻结快照的发布证明，不代表冻结之后的本机改动也已上传。

## 0.2.1 修复与真机验证

完整下载通过 SHA-256 校验后，结束只读任务时的 SSH 断开或回执超时不再阻止准备应用；其他权限与完整性错误仍失败。下载回执固定数据集、代次与清单，离线恢复会重新校验全部文件并拒绝已经进入应用的任务。文件传输 100% 与应用、重启后的同步完成分别显示。

待应用的保存失败会解除界面忙碌状态并显示原因，可使用“继续应用已下载文件”重试。插件依赖仅对明确的 npm 锁不一致错误，在候选目录重新解析锁文件后安装；原始下载与 VPS 内容保留。准备完成后重新核对本机差异，自动保存引起的变化会刷新确认并要求再次确认；确认后的真实改动仍阻止覆盖。覆盖确认绑定当前页面，避免准备期间刷新页面后一直等待旧页面交接，并继续阻止其他活跃标签页。

本机同步插件目录按实际大小写保留，不从 VPS 替换；手动恢复时先替换恢复副本中所属的同步代码目录，避免 Git 只读对象无法覆盖。Termux 入口保持终端前台运行，健康检查通过后调用 `termux-open-url`；切到浏览器时继续运行，关闭启动会话或使用 Termux 的 Exit 时退出酒馆。

Android 真机 Node.js 25.2.1 已完成真实 VPS 快照的 2,782 个文件校验、插件依赖准备、覆盖确认、保存交接、应用和受控重启。任务为 `SUCCEEDED`，替换日志为 `committed`，新实例 HTTP 200 且 epoch 匹配，前端保留正常，一次恢复副本可用。另已验证普通 Termux 管理工具选项 4 自动打开浏览器，以及 Exit 后启动器和酒馆均退出、端口与锁释放。[真机报告](test-results/termux-sync-session-android.json)。这不代表已验证 Android 反向推送或系统强制回收。

## 实际实现

0.2.0 汇总密码登录、安装目录调整、断线恢复、界面布局与 Windows 启动入口改进。未完成任务与运行锁分开：控制连接断开后，在实际 rsync 锁释放时暂停旧任务，保留暂存内容；下一次任务也能处理没有执行退出清理的旧记录。暂停的下载固定代次并阻止回收，旧上传的发布基准过期时拒绝覆盖。rsync 连接绑定设备与任务 UUID，迟到连接不能接入新任务。SSH 存活检查与 rsync 无活动超时负责回收断开的连接，不按任务总时长取消正常上传。

Windows 启动入口在所属实例通过启动检查后自动用默认浏览器打开本机酒馆，仅首次启动打开，受控同步重启不重复开页面。`--desktop-shortcut` 创建保留酒馆工作目录与图标的桌面快捷方式；已在实际桌面生成并通过该快捷方式启动验证。推送/拉取日志由父启动器持续显示到同一控制台并写入 `sync.log`，记录阶段、任务编号、rsync 文件变更/错误/统计、SSH 控制步骤与 SHA-256 校验结果。进度输出限频，逐文件变更保留，中文输出按 UTF-8 完整解码；日志不输出账号密码或文件正文。

推送失败后增加「继续上次上传」，使用相同任务号及经校验的原快照，不再停机采集；另行推送仍采集最新内容。仅在 begin 成功后记录远端任务所有权，成功后清除旧错误并更新历史与连接绑定基准。Linux 发布对只读文件使用可读描述符执行 fsync，接收文件确保同步账号可读写，避免只读属性阻止完成发布。Windows 上跳过的真实 flock 与只读 fsync 测试需在 VPS 更新时以同步账号执行。

`ui/` 是原生设置面板；`server/index.mjs` 提供继承酒馆认证与 CSRF 的本机管理员接口；`helper/launcher.mjs` 独立持有子进程、任务和 IPC，`bootstrap.mjs` 在导入酒馆前建立请求维护门控及页面代次检查。源码指纹不符时拒绝启动适配。

0.1.2 将连接表单简化为 VPS 地址、账号和密码，移除设备密钥生成及手工服务器公钥登记；数据集由首次成功连接自动读取并固定。通过 OpenSSH ASKPASS 向 SSH/rsync 提供密码，命令行和环境中只传密码文件路径；配置接口仅返回是否已保存。首次自动记录服务器身份，后续身份变化拒绝连接。VPS 增加密码登录初始化及旧版迁移脚本。

配置保存立即供父子进程使用，操作锁阻止并行任务改目标。同步基准绑定服务器、账号和数据集，换目标后重新确认覆盖。推送、拉取、手动恢复都先确认方向；手动恢复复用替换日志和受控停机，失败时尝试返回操作前状态，不修改 VPS。

本机安装入口为 `install.ps1` / `install.sh`，共用 `bin/setup-device.mjs` 安装前后端和运行库，不生成设备密钥。完整代码统一放到酒馆的 `plugins/tavernsyn`，前端界面放到 `public/scripts/extensions/third-party/tavernsyn`；只下载入口脚本时也会克隆到酒馆内，从外部完整仓库安装时复制发布代码。安装前检查端口、锁和待处理任务；重装复用已有设备身份、账号密码、VPS 配置和可用工具。已有源代码需先自行更新。Windows 需要已安装 Node 20+ 和 Git，Termux 通过 `pkg` 补齐依赖。

受控启动器实时转发子进程的标准输出和错误到启动终端，同时写入设备控制目录的 `server.log`；重启前等待旧日志写完，新进程继续向同一终端输出。Windows 入口使用 UTF-8，启动报错时暂停窗口。

受控 HTML 页面忽略旧缓存校验与范围请求，始终返回包含当前 epoch 的完整页面，并移除 ETag、Last-Modified 和范围缓存标记；HEAD 同样禁止缓存。避免 Edge 等浏览器沿用原 Start.bat 或上次启动的 HTML，导致设置读取被旧页面屏障拒绝。普通 JS/CSS 资源继续按酒馆原有规则缓存。

设置通过自己的 nonce 与可访问设置摘要读回确认，当前聊天用解析后消息及元数据摘要核对。页面真正导航到独立等待文档并 ACK 后，拒绝新请求并排空已有响应；除经核验的只读路由及 JSON 标签页心跳外，中途断连标记为不确定，不按正常完成处理。同步替换时，子进程内部触发本版本 SIGTERM 清理链路，父进程等真正退出，Windows 不使用强杀代替。

明确关闭启动终端与同步停机分开处理：Ctrl+C/SIGHUP 关闭所属生命周期，IPC 断开也会触发子进程退出，不再被不确定请求阻止；先等待在途请求最多 3 秒并执行原生清理，8 秒仍未结束则自行退出，启动器在 10 秒时为所属子进程兜底。关闭中的生命周期禁止再次启动。下次启动复用恢复工具的端口/PID 检查后清理死锁；同步停机仍严格拒绝未排空或不确定请求。

每次启动的 epoch 在 HTML 的 head 最早注入，同源 fetch/XHR 附加它。重启后的旧 API 写入返回 409，BFCache 恢复要求刷新。浏览器直接加载的 script/module/worker 请求不能附加此头，因此允许 Cocktail+ 的只读桥接脚本、Service Worker 和明确列出的五个核心模块通过；其他插件接口与写请求仍受页面代次检查。此适配不改磁盘上的酒馆 HTML，其他第三方代码共存仍需专项验收。

推送：确认保存 → 停机 → 独立快照和精简 Git → 重启 → rsync → 目标 SHA256 校验 → 原子发布。

拉取：固定代次 → rsync 暂存和校验 → 本机准备插件依赖 → 未推送修改/大批删除确认 → 保存与等待页 → 停机 → 保留设备字段 → journal 替换 → 新实例健康检查 → 成功或停机后回滚。

VPS 通过账号专属 SSH Match/ForceCommand 只接受固定入口及有限 JSON 协议，拒绝非 Tailscale 来源、交互式终端和转发。共享密码设备具有相同权限，设备 UUID 仅用于任务归属与恢复。控制会话 operation 独占锁、传输会话 transfer 共享锁，发布前进入 finalizing 再拿 transfer 独占锁。独立副本不硬链接旧代次，保留 current 与 previous 两份。
