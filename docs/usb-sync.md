# USB 数据线完整同步

USB 模式直接在 Windows 电脑和 Android Termux 手机之间同步酒馆数据，无需 VPS 或 Tailscale。每次从电脑选择一个方向：以来源设备为准，完整替换目标设备的便携数据，包含删除。

这两个入口用于**保存并关闭酒馆后的同步**。两端在传输期间都不要打开酒馆；目标应用完成后会临时启动一次进行健康检查，再正常停止。任务结束后使用平时的 TavernSyn 启动入口打开酒馆。

## 先准备什么

1. 两端已安装适配的 SillyTavern 1.19.0、Node.js 20+ 和 TavernSyn 0.3.0；分别正常启动过酒馆，用户数据目录已初始化。
2. 两端更新到同一版 TavernSyn 后，分别重新运行 `install.ps1` / `install.sh`。安装器在酒馆目录生成电脑 `USB-TavernSyn.cmd` 和手机 `usb-tavernsyn.sh`。只更新前端扩展不会生成这些入口。使用过自定义控制目录时，安装时继续指定原目录。
3. 电脑安装官方 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)。可以把其目录加入自己的 PATH，也可以直接输入 `adb.exe` 的完整路径；路径含空格可正常使用。安装器不自动下载 ADB。
4. 手机在开发者选项中开启 **USB 调试**，用能传数据的数据线连接电脑，解锁手机并允许这台电脑的调试授权。步骤见 [Android 官方 ADB 文档](https://developer.android.com/tools/adb)。首次连接可能还需要手机厂商的 Windows USB 驱动。
5. 目标设备有足够空间容纳下载暂存、准备后的候选数据及一份覆盖前备份。TavernSyn 控制目录与目标数据继续要求同一文件系统；Termux 数据放在私有 HOME 中。

USB 只负责本次数据传输。插件依赖在目标平台重新安装，首次准备依赖时可能仍需联网或已有 npm 缓存；原版酒馆和两端 Node 环境须事先安装完成。

## 每次怎么用

### 1. 保存并关闭两端酒馆

保存聊天、角色、世界书、脚本和设置，结束正在生成的回复；未发送草稿和浏览器中尚未提交的编辑不会进入快照。然后正常关闭两端的酒馆及受控启动器，等待进程退出。单独关闭浏览器标签页不等于停止酒馆。

如果还有外部脚本或独立插件进程写入这些数据，也要先正常停止。USB 入口遇到进程或任务锁占用会拒绝继续，不会强制结束未知进程。

### 2. 在手机上启动 USB 等待服务

在 Termux 中运行：

```sh
cd "$HOME/SillyTavern"
bash usb-tavernsyn.sh
```

把路径改成手机实际的酒馆目录。终端显示本次服务会话的 **32 位十六进制配对码**，保留这个窗口。配对码只交给这次连接的可信电脑；重新启动服务后使用新显示的码。

服务只监听手机本机地址，默认端口为 `17653`。ADB 通过 USB 将电脑本机端口转发到这个服务，电脑不需要通过手机 IP 地址访问。

### 3. 在电脑上选择方向

运行酒馆目录中的 `USB-TavernSyn.cmd`。按提示输入 ADB 路径（直接回车使用 PATH 中的 `adb`）、手机配对码和同步方向。

| 方向 | 来源 | 被覆盖的目标 | 命令行值 |
|---|---|---|---|
| 电脑 → 手机 | 电脑当前保存的数据 | 手机 | `push` |
| 手机 → 电脑 | 手机当前保存的数据 | 电脑 | `pull` |

程序显示双方设备名称后，核对来源与目标，输入 **`YES`** 才开始。比如电脑已经删除的聊天，在“电脑 → 手机”时也会从手机删除；手机独有但电脑没有的角色卡也会被移除。

两端各自新增的内容不会自动合并。先确定这次以哪台设备为准，再选择方向；来源设备的数据不会被目标反向覆盖。

### 4. 等待完整校验和目标检查

同步依次完成源端独立快照、完整文件传输、SHA-256 校验、目标插件依赖准备、覆盖前备份、事务替换和启动健康检查。文件传输结束还不代表应用完成。

目标健康检查会临时启动酒馆，核对实例和服务端插件是否正常，再正常停止。期间不要从其他入口启动或访问酒馆，也不要关闭终端、拔线或手动移动暂存目录。

确认任务完成后，手机 USB 服务自动退出；若电脑提示对端退出尚未确认，在手机终端按 Ctrl+C 结束服务。然后用 `Start-TavernSyn.cmd` / `start-tavernsyn.sh` 正常启动各自酒馆。

## 完整同步包括哪些内容

USB 使用与 TavernSyn 完整同步相同的便携范围：绑定用户的聊天和群聊、角色卡与资源、世界书、预设、正则、Quick Replies、人格、图片与附件、主题、自定义数据、API 配置与密钥，以及前后端插件工作文件和固定 Git 版本。已配置的额外目录按相同 `id` 映射到目标本机路径。

设备网络、端口、账户身份、SSH/Tailscale 凭据和精确指定的本机设置字段继续保留。酒馆核心程序、其他用户账户、浏览器 localStorage/IndexedDB、缓存、历史聊天备份、跨平台 `node_modules` 和 TavernSyn 自身安装代码不进入镜像。

目标平台恢复插件依赖；插件带有不能跨平台使用的原生二进制时会拒绝应用。具体范围、额外目录和本机字段规则见[同步范围](scope.md)。

## 只保留最新一份备份

**备份是本次覆盖前的目标设备数据，用于撤销这次覆盖。** 它不是来源快照，也不是覆盖完成后的另一个副本。

- 每台设备只保留一份 TavernSyn 覆盖前恢复备份，VPS 拉取和 USB 接收共用这份备份。
- 下一次真正准备覆盖该设备时，先清理上一份已完成任务的备份，再创建本次备份。传输、校验或依赖准备失败时，不会提前清掉现有可用备份。
- 新数据应用和健康检查成功后，新备份继续保留；下一次实际覆盖才替换它。
- 仅从本机导出、推送到 VPS、预览或检查无变化，不会消费本机最近的有效备份。
- 未完成的应用或恢复记录需要先处理，不能通过清理备份绕过。

备份位于设备控制目录的 `recovery/`，替换日志是 `apply.json`。需要撤销时，从正常 TavernSyn 入口启动目标酒馆，在扩展面板点击 **恢复上一版**。恢复只影响本机，不修改另一台设备或 VPS；成功恢复后该份备份已被使用，不再保留为第二个历史版本。详见[恢复说明](recovery.md)。

这里的“一份”指 TavernSyn 的覆盖前恢复备份。SillyTavern 自己的聊天历史备份不作为同步内容传输，相关备份设置仍按既有配置白名单同步，详见[同步范围](scope.md)。

## 命令行与多设备

以下命令在已安装的 TavernSyn 代码目录运行，`--state` 是对应设备原有的控制目录，不能填成酒馆目录。

手机端：

```sh
node bin/usb.mjs --state "$HOME/.tavernsyn-SillyTavern" --mode serve
```

电脑端交互方式：

```powershell
node bin/usb.mjs --state "D:/TavernSyn-device" --mode client
```

指定电脑 ADB 路径与手机序列号：

```powershell
node bin/usb.mjs --state "D:/TavernSyn-device" --mode client --adb "C:/Android SDK/platform-tools/adb.exe" --serial "手机序列号"
```

需要更换服务端口时，两端都追加相同的 `--port 17654`。电脑本地转发端口由 ADB 自动分配，不需要与手机服务端口相同。

脚本调用可显式传入全部确认参数：

```text
node bin/usb.mjs --state "设备控制目录" --mode client --adb adb --direction push --token "本次32位十六进制配对码" --confirm yes
```

`--direction pull` 表示手机覆盖电脑。日常建议使用交互入口，避免把配对码留在命令历史、脚本或进程参数中；不要将真实配对码提交到仓库。

默认只连接唯一已授权的 USB 手机；连接多台时可用 `--serial` 指定。Windows 原生 ADB 有时不提供 USB 设备路径，这时程序要求只连接一台 USB 手机并核对序列号，即使指定了 `--serial` 也不会凭猜测继续。无线 ADB 和模拟器不作为本功能的连接目标。

## 失败时怎么处理

| 情况 | 处理 |
|---|---|
| 找不到 `adb` | 安装官方 Platform-Tools，输入 `adb.exe` 完整路径；不能使用 `.cmd` 或 `.bat` 包装脚本。 |
| 手机未授权 / 离线 | 解锁手机，允许电脑的 USB 调试授权；必要时重新插拔数据线。 |
| 找到多台设备 | 指定 `--serial`；Windows 原生后端无法确认 USB 路径时，只连接目标手机。 |
| 配对码错误或失效 | 使用手机当前 USB 服务窗口显示的码；服务重启后旧码不再适用。 |
| 手机服务连接失败 | 确认手机 USB 入口仍运行，两端 `--port` 一致，数据线和调试授权正常。 |
| 仍有酒馆或同步进程 | 正常关闭对应进程；异常锁按[恢复说明](recovery.md)处理，不手动删锁。 |
| 校验或插件依赖准备失败 | 目标数据尚未覆盖；查看错误和任务日志，修复后重新发起。 |
| 应用前拔线或传输中断 | 不完整载荷不会应用；重新连接并启动新的完整同步，不是从断点继续。 |
| 目标应用期间拔线、客户端超时 | 以目标设备自己的终端、任务状态和替换日志为准；电脑未收到成功回执不代表目标没有应用。先核对目标，避免盲目再次覆盖。 |
| 启动健康检查或回滚失败 | 保留控制目录、`apply.json`、`recovery/` 与任务目录，按[恢复说明](recovery.md)处理。 |

USB 连接结束时仅移除本任务仍然匹配的端口转发，不清理其他应用的 ADB 转发。关闭手机服务后本次配对入口结束。

## 当前限制与验证边界

本地 Linux 验证记录见 [usb-sync-linux.json](test-results/usb-sync-linux.json)：整合后的 Node 测试 280 项，277 项通过、3 项 Windows 专属检查跳过；其中新增 USB 测试 53 项全部通过。另有 40 项 VPS Python 测试、8 项独立 rsync 检查和 32 项既有真实酒馆集成检查通过。USB 专项使用真实 HTTP 流和固定版 SillyTavern 进程，验证两个方向的完整应用、启动健康检查、本机字段保留及备份恢复。GitHub Actions 另运行 Windows / Node 20 的 USB 协议与入口检查，以及 Linux 完整集成。

本版按文件流式传输完整快照，逐文件及最终清单校验，不提供 rsync 增量、压缩或断点续传；大数据集的首次与后续同步都应预留完整传输时间和暂存空间。USB 传输本身不走 VPS，也不负责在线安装或升级 SillyTavern。

自动化验证可以覆盖 ADB 命令选择与清理归属、流式文件协议、隔离目录中的应用和恢复。当前尚未使用 Windows 电脑与 Android 实体手机完成本版 USB 数据线验收，不能据此保证所有手机厂商驱动、Android 后台回收行为及数据线组合都已验证。进程中断恢复也不等同突然断电后的硬盘持久性验收。

实现依据：[Android ADB](https://developer.android.com/tools/adb)、[ADB 命令手册](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)、[Termux 私有文件系统布局](https://github.com/termux/termux-packages/wiki/Termux-file-system-layout)。Termux 内部进程读取自己的私有数据，ADB 仅转发本机端口，不依赖直接访问手机私有目录。
