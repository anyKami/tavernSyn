# USB 数据线完整同步

USB 模式直接在 Windows 电脑和 Android Termux 手机之间同步酒馆数据，无需 VPS 或 Tailscale。当前指南对应 **TavernSyn 0.7.0**。两端在插件中连接后，在任意一端选择方向即可开始。程序通过数据线传输完整来源快照，按快照覆盖目标设备的便携数据，包含删除。

## 推荐：直接在插件中操作

使用平时的受控入口启动 Windows 和 Termux 两端酒馆。扩展面板中的 **USB 数据线完整同步** 是靠前的醒目卡片，默认展开，连接与方向按钮至少 48 CSS px 高；安卓窄屏会调整按钮布局。旁边的 **设置与检查 · 同步仓库** 也可以点击整行展开。

1. 用数据线连接两台设备，在两端 USB 卡片分别点击 **连接 USB**。
2. 显示已连接后，在任意一端点击 **电脑 → 手机** 或 **手机 → 电脑**，另一端自动跟随。
3. 启动器自动关闭酒馆、制作并传输完整来源快照、校验并应用快照、执行目标启动检查，再重新启动两端酒馆。

**点击方向即执行，按钮立即切换为已发起状态，进度显示在 TavernSyn 扩展的 USB 卡片内。** 卡片显示已传输字节、文件数和百分比，并分别显示校验、应用和重启阶段。受控启动器在酒馆关闭时临时接管同一端口的只读状态查询，酒馆重启后切回正常页面。传输达到 100% 后，等到两端重启完成再拔线。Android 首次 USB 调试授权需要在系统弹窗中允许。由你选择按哪台设备的数据覆盖另一台。

连接前会自动停止生成，每次自动保存最多尝试 1.5 秒，保存未及时完成时自动继续，以停机后的实际磁盘数据为准；不需要先清空草稿、关闭编辑弹窗或其他酒馆标签页。未保存的瞬时内容可能丢失。关闭时立即停止旧实例连接，最多给原生退出 2 秒宽限，卡住则自动结束启动器所属进程；观察到进程真正退出后才处理快照或覆盖文件。文件校验、单份备份和事务恢复照常自动执行。

关闭浏览器不等于终止后台任务；操作中不要再启动第二个酒馆实例。两个方向都会进行完整镜像，目标设备独有数据可能被删除。本机恢复备份只保留上一版。

## 全量传输如何工作

每次同步都发送来源快照内的全部文件，包括接收端已存在的相同文件。接收端按来源快照替换便携数据，删除来源已没有的文件，保留接收设备的本机设置和覆盖前备份。

1. 两端停机后读取本机文件属性，用于检测同步期间的意外改动。两端都更新后，接收端的准备可与来源快照同时进行。
2. 来源复制快照时计算逐文件 SHA-256，并通过 USB 流式发送快照。
3. 接收端在传输时逐文件校验 SHA-256，随后复制出独立的应用副本。复制时计算副本内容的 SHA-256 并核对完整清单，减少单独读取文件的次数。
4. 接收端在校验副本并确保其落盘后，保留本次覆盖前备份并执行事务替换。替换后读取实际数据作为同步基线，再执行启动健康检查。应用失败时按替换日志恢复。

全量流程省去接收基准快照和两端内容比较。实际耗时取决于完整快照大小、两端存储速度、数据线传输速度、插件依赖准备和启动检查。

能力协商自动完成。建议两端都更新至 0.7.0 或更新版本，以使用完整的流程优化。与兼容的旧版 USB v2 对端连接时，自动使用原有全量流程。比 0.5.0 更早的 USB 协议须先更新。

## 备用：使用独立脚本

以下离线入口保留用于无法通过插件界面连接的情况下。使用离线入口前必须先关闭两端酒馆及受控启动器，想保留的编辑应先保存。目标应用完成后会临时启动一次进行健康检查，再快速停止。任务结束后使用平时的 TavernSyn 启动入口打开酒馆。

## 使用前准备

1. 两端已安装通过源码指纹检查的 SillyTavern 和 Node.js 20+，建议均使用 **0.7.0 或更新版本 TavernSyn**。两端均正常启动过酒馆并初始化用户数据目录。[安装前提](installation.md#前提与目录)
2. 两端更新后可继续使用已有的电脑 `USB-TavernSyn.cmd` 和手机 `usb-tavernsyn.sh`。酒馆目录还没有 USB 入口时，再运行 `install.ps1` / `install.sh` 生成；只更新前端扩展不会生成入口。使用过自定义控制目录时，安装时继续指定原目录。
3. 电脑安装官方 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)，把其目录加入自己的 PATH。USB 入口会直接查找 `adb`；安装器不自动下载 ADB。未配置 PATH 时，可按后文的高级命令使用 `--adb` 指定完整路径。
4. 手机在开发者选项中开启 **USB 调试**，用能传数据的数据线连接电脑，解锁手机并允许这台电脑的调试授权。步骤见 [Android 官方 ADB 文档](https://developer.android.com/tools/adb)。首次连接可能还需要手机厂商的 Windows USB 驱动。
5. 来源设备须有足够空间制作完整快照。接收设备须能容纳完整暂存快照、独立应用副本、目标平台插件依赖和一份覆盖前备份。TavernSyn 控制目录与目标数据必须在同一文件系统。Termux 数据放在私有 HOME 中。

USB 只负责本次数据传输。插件依赖在目标平台重新安装，首次准备依赖时可能仍需联网或已有 npm 缓存；原版酒馆和两端 Node 环境须事先安装完成。

## 离线脚本每次怎么用

两端 USB 入口都需要保持运行。电脑入口先打开时，会自动等待手机入口最多 2 分钟；手机已经就绪时直接连接。连接后只需在任意一端选一次方向。

### 1. 保存并关闭两端酒馆

保存聊天、角色、世界书、脚本和设置，结束正在生成的回复；未发送草稿和浏览器中尚未提交的编辑不会进入快照。然后正常关闭两端的酒馆及受控启动器，等待进程退出。单独关闭浏览器标签页不等于停止酒馆。

如果还有外部脚本或独立插件进程写入这些数据，也要先正常停止。USB 入口遇到进程或任务锁占用会拒绝继续，不会强制结束未知进程。

### 2. 打开两端 USB 入口

在 Termux 中运行：

```sh
cd "$HOME/SillyTavern"
bash usb-tavernsyn.sh
```

把路径改成手机实际的酒馆目录，并保留终端窗口。电脑运行酒馆目录中的 `USB-TavernSyn.cmd`。程序自动识别已通过 USB 调试授权的手机，建立本次连接。

### 3. 在任意一端选择方向

电脑和手机提供同一组选项，选择任意一端操作即可：

| 选项 | 来源 | 被覆盖的目标 | 命令行值 |
|---|---|---|---|
| `1` 电脑 → 手机 | 电脑当前保存的数据 | 手机 | `push` |
| `2` 手机 → 电脑 | 手机当前保存的数据 | 电脑 | `pull` |

选定后直接开始，另一端自动停止等待选择并显示任务进度。如果两端同时选择，以先被接受的方向为准，只启动一个任务。

选择前看清来源与目标：比如电脑已经删除的聊天，在“电脑 → 手机”时也会从手机删除；手机独有但电脑没有的角色卡也会被移除。两端各自新增的内容不会自动合并，应先确定这次以哪台设备为准。

### 4. 等待完整校验和目标检查

同步会传输完整来源快照，执行 SHA-256 校验、目标插件依赖准备、覆盖前备份、事务替换和启动健康检查。请等到终端显示同步完成后，再关闭入口或拔线。

目标健康检查会临时启动酒馆，核对实例和服务端插件是否正常，再快速停止。期间不要从其他入口启动或访问酒馆，也不要关闭终端、拔线或手动移动暂存目录。

任务完成后，手机 USB 服务自动退出，Windows USB 入口不再等待按键；若电脑提示对端退出尚未确认，在手机终端按 Ctrl+C 结束服务。然后用 `Start-TavernSyn.cmd` / `start-tavernsyn.sh` 正常启动各自酒馆。需要持续查看离线入口的输出时，在已经打开的 PowerShell/CMD 中运行它。

## 完整同步包括哪些内容

USB 使用与 TavernSyn 完整同步相同的便携范围：绑定用户的聊天和群聊、角色卡与资源、世界书、预设、正则、Quick Replies、人格、图片与附件、主题、自定义数据、API 配置与密钥，以及前后端插件工作文件和固定 Git 版本。已配置的额外目录按相同 `id` 映射到目标本机路径。

设备网络、端口、账户身份、SSH/Tailscale 凭据、Google 授权与仓库密钥，以及精确指定的本机设置字段继续保留。酒馆核心程序、其他用户账户、浏览器 localStorage/IndexedDB、缓存、历史聊天备份、跨平台 `node_modules` 和 TavernSyn 自身安装代码不进入镜像。

目标平台恢复插件依赖；插件带有不能跨平台使用的原生二进制时会拒绝应用。具体范围、额外目录和本机字段规则见[同步范围](scope.md)。

## 只保留最新一份备份

**备份是本次覆盖前的目标设备数据，用于撤销这次覆盖。** 它不是来源快照，也不是覆盖完成后的另一个副本。

- 每台设备只保留一份 TavernSyn 覆盖前恢复备份，VPS 拉取、Google 云盘拉取和 USB 接收共用这份备份。
- 下一次真正准备覆盖该设备时，先清理上一份已完成任务的备份，再创建本次备份。传输、校验或依赖准备失败时，不会提前清掉现有可用备份。
- 新数据应用和健康检查成功后，新备份继续保留；下一次实际覆盖才替换它。
- 仅从本机导出、推送到远端仓库、预览或检查无变化，不会消费本机最近的有效备份。
- 未完成的应用或恢复记录需要先处理，不能通过清理备份绕过。

备份位于设备控制目录的 `recovery/`，替换日志是 `apply.json`。需要撤销时，从正常 TavernSyn 入口启动目标酒馆，在扩展面板点击 **恢复上一版** 即执行，无需再次确认。恢复只影响本机，不修改另一台设备或远端仓库；成功恢复后该份备份已被使用，不再保留为第二个历史版本。详见[恢复说明](recovery.md)。

这里的“一份”指 TavernSyn 的覆盖前恢复备份。SillyTavern 自己的聊天历史备份不作为同步内容传输，相关备份设置仍按既有配置白名单同步，详见[同步范围](scope.md)。

## 命令行与多设备

以下命令在已安装的 TavernSyn 代码目录运行，`--state` 是对应设备原有的控制目录，不能填成酒馆目录。

手机端：

```sh
node bin/usb.mjs --state "$HOME/.tavernsyn-SillyTavern" --mode serve
```

电脑端交互方式：

```powershell
node bin/usb.mjs --state "D:/TavernSyn-device" --mode client
```

指定电脑 ADB 路径与手机序列号：

```powershell
node bin/usb.mjs --state "D:/TavernSyn-device" --mode client --adb "C:/Android SDK/platform-tools/adb.exe" --serial "手机序列号"
```

手机服务只监听本机地址，默认端口为 `17653`，ADB 经 USB 转发连接。需要更换服务端口时，两端都追加相同的 `--port 17654`。电脑本地转发端口由 ADB 自动分配，不需要与手机服务端口相同。

脚本调用可在任意一端显式指定方向。例如，由手机选择“电脑 → 手机”：

```sh
node bin/usb.mjs --state "$HOME/.tavernsyn-SillyTavern" --mode serve --direction push
```

或者由电脑选择“手机 → 电脑”：

```powershell
node bin/usb.mjs --state "D:/TavernSyn-device" --mode client --direction pull
```

两端的 `--direction` 含义相同：`push` 始终是电脑覆盖手机，`pull` 始终是手机覆盖电脑。另一端仍需运行自己的 USB 入口；只需一端指定方向，连接成功并接受该方向后自动开始。非交互运行时不指定方向，会等待对端选择。

默认只连接唯一已授权的 USB 手机；连接多台时可用 `--serial` 指定。Windows 原生 ADB 有时不提供 USB 设备路径，这时程序要求只连接一台 USB 手机并核对序列号，即使指定了 `--serial` 也不会凭猜测继续。无线 ADB 和模拟器不作为本功能的连接目标。

## 失败时怎么处理

| 情况 | 处理 |
|---|---|
| 找不到 `adb` | 安装官方 Platform-Tools 并加入 PATH，或重新运行命令追加 `--adb "adb.exe完整路径"`；不能使用 `.cmd` 或 `.bat` 包装脚本。 |
| 手机未授权 / 离线 | 解锁手机，允许电脑的 USB 调试授权；必要时重新插拔数据线。 |
| 找到多台设备 | 指定 `--serial`；Windows 原生后端无法确认 USB 路径时，只连接目标手机。 |
| USB 协议或版本不匹配 | 将两端更新到 0.7.0 或更新的同一版本，然后重新启动两端酒馆。重新运行离线脚本前先关闭旧 USB 窗口。 |
| 手机服务连接失败 | 插件模式检查手机酒馆仍受控运行并已点击连接；离线模式检查手机 USB 脚本仍运行且两端 `--port` 一致。核对数据线和调试授权。 |
| 仍有酒馆或同步进程 | 正常关闭对应进程；异常锁按[恢复说明](recovery.md)处理，不手动删锁。 |
| 校验或插件依赖准备失败 | 目标数据尚未覆盖；查看错误和任务日志，修复后重新发起。 |
| 应用前拔线或传输中断 | 重新连接并发起新任务，从头发送完整快照。接收端仅应用完整校验通过的载荷。 |
| 目标应用期间拔线、客户端超时 | 以目标设备自己的终端、任务状态和替换日志为准；电脑未收到成功回执不代表目标没有应用。先核对目标，避免盲目再次覆盖。 |
| 启动健康检查或回滚失败 | 保留控制目录、`apply.json`、`recovery/` 与任务目录，按[恢复说明](recovery.md)处理。 |

USB 连接结束时仅移除本任务仍然匹配的端口转发，不清理其他应用的 ADB 转发。关闭手机服务后本次连接结束。

## 当前限制与验证边界

自动化测试检查 USB 自动连接、并发方向选择、完整快照传输，以及隔离目录中的应用和恢复。真实 HTTP 与固定版 SillyTavern 集成检查验证两个方向的全量传输、启动健康检查、本机字段保留及备份恢复。历史记录对应 0.3.0。[usb-sync-linux.json](test-results/usb-sync-linux.json)

0.5.1 的共享快速停机流程已有 17 项生命周期单元测试和 33 项实际 SillyTavern 1.19.0 隔离集成检查通过。Linux / Node 24.22.3 中，故意挂起插件退出清理时，同步停机 2035 ms、终端关闭 2023 ms，并验证所属实例锁清理和同端口重新启动。这个耗时测试不包含 USB 文件传输和安卓真机。

本版传输完整文件流，压缩和断点续传尚未提供。传输统计按文件内容字节计算，HTTP、清单及协商开销另计。

Windows 电脑与 Android 实体手机的数据线验收和端到端耗时仍待测量。自动化测试中的持久性验证覆盖进程中断恢复。

实现依据：[Android ADB](https://developer.android.com/tools/adb)、[ADB 命令手册](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)、[Termux 私有文件系统布局](https://github.com/termux/termux-packages/wiki/Termux-file-system-layout)。Termux 内部进程读取自己的私有数据，ADB 仅转发本机端口，不依赖直接访问手机私有目录。
