# Google 云盘同步仓库

Google 云盘可以保存 TavernSyn 的完整同步副本。电脑和手机各自运行酒馆，分别向同一个仓库推送、从仓库拉取，不要求两台设备同时在线，也不需要 VPS、SSH 或 Tailscale。

此功能从 0.4.0 起提供；建议两端更新到 **0.5.0 或更新版本**，使用增强的旧快照与失败上传清理。它使用现有的受控保存、停机快照、下载校验、应用、启动检查和恢复流程。Google 云盘只保存文件，不运行酒馆或服务端程序。

## 适用范围

| 项目 | Google 云盘方式 |
| --- | --- |
| 同步内容 | 当前绑定用户的可迁移完整内容，包括聊天、角色、世界书、预设、图片、API 配置与密钥，以及前后端插件和已配置的自定义目录 |
| 本机保留项 | 端口、网络、账户、设备配置及基础设施凭据；SillyTavern 本体和平台依赖仍由各设备管理 |
| 传输 | 完整快照先压缩，再在本机用 AES-256-GCM 加密，经 HTTPS 上传；拉取后验证、解密并逐文件核对 SHA-256 |
| 使用方式 | 酒馆内手动推送、拉取和预览；确认一次方向与覆盖范围后自动执行 |
| 分类同步 | 当前不提供；聊天、角色和世界书的分类增量入口仍用于 VPS |
| 备份数量 | 发布并清理成功后，云端保留最新一份完整快照和少量仓库记录；每台设备另保留最新一次覆盖前的本机恢复备份 |
| 同时修改 | 不合并聊天和设置。两台设备同时发布时只允许一个提交成功，另一台需重新检查仓库后决定推送或拉取 |

“完整”指[同步范围](scope.md)定义的可迁移内容，不是复制整个磁盘。浏览器数据库、尚未保存的编辑、SillyTavern 本体、其他用户目录及平台专用 `node_modules` 不进入快照。恢复插件依赖可能仍需 npm 缓存或网络。

## 一、准备自己的 Google OAuth 应用

TavernSyn 没有内置共用的 Google 客户端。首次配置需要你的 Google Cloud 项目和一个 **桌面应用（Desktop app）** OAuth 客户端；电脑和手机填写同一个客户端，并授权同一个 Google 账号。

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)，创建或选定专门用于 TavernSyn 的项目。
2. 在 API 库中启用 **Google Drive API**。
3. 在 Google Auth Platform 中配置应用名称、支持邮箱和受众。个人 Google 账号通常选择 **External**；测试期间把自己的账号加入测试用户。
4. 在 Data Access 中声明 `https://www.googleapis.com/auth/drive.file`。TavernSyn 只请求此范围，用于操作该 OAuth 应用创建的文件。
5. 在 Clients 中新建 **Desktop app** 客户端，下载客户端 JSON，记录其中的 `client_id` 和 `client_secret`。
6. 用于长期个人同步时，将 OAuth 应用的发布状态设为 **In production**。External 应用停留在 Testing 状态时，Drive 授权的刷新令牌通常会在 7 天后失效，需要重新授权。发布 OAuth 应用不会公开你的云盘文件。

不要选择 Web application 或 Android 类型，也不要配置已经停用的手工复制授权码流程。TavernSyn 的 Node 命令行进程采用桌面应用授权方式：打开系统浏览器，使用 PKCE 和随机 `state`，通过本机 `127.0.0.1` 随机端口接收结果。

Google 界面名称可能调整，具体规则见官方的[桌面应用 OAuth 说明](https://developers.google.com/identity/protocols/oauth2/native-app)、[Drive 授权范围说明](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)和[刷新令牌失效条件](https://developers.google.com/identity/protocols/oauth2#expiration)。是否需要额外验证由 Google 对该应用的提示决定；不要为排错扩大到整个云盘的授权范围。

## 二、第一台设备创建仓库

先按[安装指南](installation.md)安装或更新 TavernSyn，从 `Start-TavernSyn.cmd` / `start-tavernsyn.sh` 正常受控启动酒馆。

1. 打开 **扩展设置 → TavernSyn 跨设备同步 → 设置与检查 · 同步仓库**。
2. 将“存储位置”选为 **Google 云盘**。
3. 填写上一步的客户端 ID 和客户端密钥，点击 **保存配置**。
4. 点击 **授权 Google 账号**。在打开的 Google 页面完成授权，再返回酒馆；状态会自动刷新。浏览器阻止新窗口时，可以点击面板里的授权链接。
5. 点击 **创建新仓库**。程序在“我的云端硬盘”中创建 TavernSyn 专用目录，并生成仓库解密密钥。
6. 复制显示的 **仓库配对码**，保存到自己的密码管理器或其他可信位置。关闭弹窗会清除页面里的配对码；以后可点击“显示仓库配对码”重新取得。
7. 点击 **检查连接**，确认仓库可以访问。

仓库配对码含仓库标识和解密密钥，不含 Google access token 或 refresh token。云盘授权和配对码缺一不可。失去所有设备上的配对信息及其备份后，TavernSyn 无法替你解密云端快照。

首次创建的仓库是空的。应在数据完整的设备上先点击 **推送到 Google 云盘**；完成后再让另一台设备拉取。单纯创建仓库不会上传酒馆内容。

## 三、第二台设备加入同一个仓库

1. 安装相同版本，正常受控启动酒馆。
2. 在设置中选择 Google 云盘，填写**同一组** OAuth 客户端 ID 和客户端密钥，保存。
3. 点击“授权 Google 账号”，选择**同一个** Google 账号。
4. 在“加入已有仓库”中粘贴第一台设备的仓库配对码，点击 **加入这个仓库**。
5. 检查连接，核对数据集与第一台设备相同，然后点击 **从 Google 云盘拉取**。

第二台设备无需再创建一个新仓库。Google Drive 允许同名文件夹，两个同名的 TavernSyn 文件夹也可能是完全不同的仓库；程序按固定 ID 识别，以配对码和数据集为准。

已经绑定仓库的设备可以重复导入同一配对码，但本版不允许直接用另一仓库或 OAuth 应用覆盖现有密钥。迁移前保存原配对码，并使用独立的设备控制目录，避免一次错误配置丢失唯一解密信息。

### Android Termux 授权

在手机上打开由本机 Termux 启动的酒馆页面，点击授权，并在**同一部手机**的系统浏览器完成 Google 登录。保持 Termux 和酒馆启动窗口运行，授权回调需要访问该手机上的 `127.0.0.1` 监听端口。把授权链接发给电脑打开无法回到手机的本机监听器。

这里运行的是 Node/Termux 命令行进程，使用上面创建的 Desktop app 客户端；不要另建 Android OAuth 客户端来使用 loopback 回调。Google 官方已停用 Android 客户端类型的这种回调方式。本次自动化测试不等同于实际 Google 账号和具体手机浏览器的授权验收。

### 手机浏览器不能完成授权时

可以先在自己的 Windows 设备完成授权，再通过可信的 USB 文件传输将授权导入手机。**授权文件含 Google 离线访问令牌**，应只交给自己的设备，导入后删除临时文件。它与仓库配对码分开：授权文件允许访问云盘，配对码提供仓库位置和解密密钥。

先正常关闭两端酒馆和 TavernSyn 启动器。Windows PowerShell 中执行，路径替换为实际安装及控制目录：

```powershell
node "D:\SillyTavern\plugins\tavernsyn\bin\drive-credentials.mjs" --state "D:\.tavernsyn-SillyTavern" --export "$env:USERPROFILE\tavernsyn-google-auth.json"
```

导出文件必须位于酒馆及同步范围之外，且不能覆盖同名已有文件。将它安全传入手机的 Termux 私有目录后执行：

```sh
chmod 600 "$HOME/tavernsyn-google-auth.json"
node "$HOME/SillyTavern/plugins/tavernsyn/bin/drive-credentials.mjs" --state "$HOME/.tavernsyn-SillyTavern" --import "$HOME/tavernsyn-google-auth.json"
```

若经手机下载目录中转，先复制到 Termux 私有 HOME；不要把凭据长期留在共享存储。导入成功后删除两端的临时授权文件，再正常启动酒馆。手机面板会显示账号已授权，随后仍需粘贴第一台设备的仓库配对码并加入仓库。已有绑定的设备只接受同一 OAuth 客户端的授权文件。

## 日常使用

建议每次切换设备按下面的顺序操作：

1. 在当前设备保存聊天和各编辑器内容，关闭其他酒馆标签页。
2. 点击“推送到 Google 云盘”，核对方向后确认。程序短暂停机制作快照，随后重启酒馆并完成上传；快照之后产生的新修改留待下一次推送。
3. 在另一设备点击“从 Google 云盘拉取”。下载和校验完成后，程序保存、停机、替换内容并进行启动健康检查。
4. 等面板显示完成，再继续使用。

推送以本机为准更新云端完整镜像，拉取以云端为准更新本机，均包含删除。两台设备独立修改后不会自动合并；不确定时先预览并保留需要的内容，再选择方向。

Google 云盘与 VPS 配置可分别保留，通过“存储位置”选择并保存后切换。按钮和确认框会显示当前**已保存**的目标，只有在下拉框改选而未保存时，仍使用原目标。切换仓库不会自动把 VPS 上的内容迁移到 Google 云盘；应从有完整数据的设备推送。

## 发布、并发与清理

云端存储由加密快照和小型仓库记录组成。每次上传使用新的文件 ID；只有上传及校验完成、提交记录发布成功后，新快照才成为当前版本。旧的有效快照在此之前保留。新版本发布后，程序永久删除已被替代且能核实归属的旧快照，也会清理有可靠任务记录的失败上传文件。

清理采用永久删除，旧文件不会只被移入回收站继续留存；本仓库已在回收站中的可清理旧快照和失败文件也会处理。操作按仓库记录核对文件 ID，不清空整个云盘回收站，也不删除其他文件。

删除方式使用 Google Drive 的 [files.delete 接口](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/delete)。云盘界面的容量统计可能延迟更新，见 [Google 存储空间说明](https://support.google.com/drive/answer/6374270?hl=zh-Hans)。

提交记录预先指定唯一的下一提交 ID。两个设备争用同一位置时，Google Drive 只允许一次创建成功；另一个收到版本变化错误。提交记录很小，保留它们是为了验证发布顺序、判断响应丢失后的结果和定位当前快照，**不保留对应的旧酒馆完整备份**。不要手动删除或修改专用目录里的仓库描述和提交记录。

上传中断不会先删除唯一的已发布快照。同一次任务可以重试分块上传；跨进程重启后的继续上传可能需要重新发送完整加密快照，当前不提供 VPS 的 rsync 块差分。未确认发布的任务不能被当作成功；如果界面提供“核对同步结果”，先核对再决定是否重试。

如果断网或权限问题导致删除失败，相关文件可能暂时留存。程序保留清理记录，在连接仓库时重试，包括检查连接、预览和推送/拉取建立连接；发布前后及任务结果核对时也会重试。未提交的上传文件不参与拉取或应用。不能证明已结束的未知上传会保留，避免误删另一设备正在使用的文件。

旧版本中断后遗留、又没有提交记录或有效任务记录可证明可以删除的孤立文件，会保留并报告数量，需核对来源后单独处理。“只保留一份”指正常发布并完成清理后的完整快照数；故障、旧遗留文件和并发上传都可能带来额外占用。

### 需要预留多少空间

上传期间，新快照和当前有效快照会短暂并存，云盘应有空间容纳这两份内容及少量仓库记录。多个设备同时上传、网络中断或清理失败时，占用还可能增加。程序会保护当前有效快照，不会先删掉它来勉强腾出本次上传空间；空间不足时应处理自己的其他文件或已确认的遗留任务，再重试。

小型提交记录用于确定版本和并发归属，任务记录用于清理重试，这些记录不包含旧酒馆的完整内容。正常完成后云端保留仓库描述、提交记录和最新完整快照。设备本机还需要独立快照、加密包、下载暂存和恢复备份的临时空间，不能只按云端压缩包大小估算本机所需容量。

本机备份遵循现有单份策略：下一次**实际覆盖**前替换旧恢复备份，成功后保留本次覆盖前的副本。Google 拉取、VPS 拉取和 USB 接收共用这一份本机恢复备份。推送、预览和无变化检查不删除它；点击“恢复上一版”只恢复本机，不修改云端当前快照。

## 凭据与数据

Google 令牌、OAuth 客户端配置和仓库解密密钥保存在酒馆之外的设备受限控制目录，不进入同步快照、不回显到常规配置接口或日志。普通设置页面不会显示已保存的客户端密钥。配对码只在显式点击后显示，关闭即清除页面内容；剪贴板由系统管理。

完整快照内包含酒馆 API 密钥和聊天正文。它在上传前经过加密，Google 云盘里保留密文；本机酒馆、暂存和恢复目录仍按原有方式保存数据。拥有同一 Google 账号授权和仓库配对码的设备可以读取及发布仓库内容，请仅在自己的可信设备使用。

“移除本机 Google 授权”只移除本机保存的授权，不删除云端仓库。需要从 Google 账号撤销应用权限时，可在账号的第三方应用连接设置中操作；撤销后所有相关设备可能需要重新授权。不要把设备控制目录、OAuth 下载文件或配对码提交到 GitHub。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 授权页面提示应用仍在测试或无权使用 | 在 Google Auth Platform 中将自己的账号加入测试用户，或完成适用的发布设置；核对选择的账号和项目 |
| 数日后提示授权失效 / `invalid_grant` | 重新授权，并检查 External 应用是否仍处于 Testing 状态、是否撤销过权限，以及 Google 账号的相关安全设置 |
| 授权完成后打不开本机回调 | 保持对应设备的 Termux/启动器运行，并在该设备的浏览器完成授权；重新开始一次授权，避免使用过期链接 |
| 加入仓库提示不存在或无权访问 | 核对两端 Google 账号与 OAuth 客户端相同，再从首台设备重新复制配对码；不要使用同名目录推测仓库 |
| 解密或仓库验证失败 | 重新核对完整配对码；不要手工编辑仓库标识或密钥，也不要删除当前设备数据来排错 |
| 推送提示远端已经变化 | 另一设备已发布。先预览/拉取新内容，或在明确要保留本机版本时重新发起一次推送 |
| Google 云盘空间不足、配额或网络错误 | 释放自己确认可删的其他文件、检查网络后重试；程序在新版本确认前保留当前有效快照 |
| 推送已完成，但提示旧快照清理未完成 | 检查网络和仓库权限，后续连接、推送或核对任务结果时会重试；清理完成前旧文件可能仍占空间 |
| 下载时旧代次已被清理 | 另一设备刚完成新发布；重新拉取当前代次，尚未验证的下载不会覆盖本机 |

## 验证范围

仓库内的自动化测试使用隔离目录和模拟 Google HTTP/API，覆盖发布竞争、异常响应、校验、加密、凭据边界以及现有受控同步流程。它们不需要或访问你的 Google Drive 账号。实际 Google OAuth 授权、账号配额、地区网络及手机后台行为需要在首次配置时以“检查连接”和一次实际推送/拉取确认；未通过真实账号验证的场景不能宣称已经实测。
