# 分类增量同步

0.2.6 增加“仅同步所选内容”入口。聊天记录、角色卡、世界书可以单独选择，也可以组合选择；支持推送、拉取和各自的预览。

## 使用

1. 本机 TavernSyn 前端、后端以及 VPS 服务程序均更新到 0.2.6 或后续兼容版本。VPS 需要声明 `scoped-sync-v1` 能力；旧 VPS 会在停机或传输之前被明确拒绝，不会退回完整同步。
2. VPS 需先有一份完整推送建立的同步副本。
3. 在“仅同步所选内容”中勾选类别，点击分类预览核对差异，或直接点击分类推送/拉取。
4. 确认实际新增、修改和删除数量。所选类别以来源为准，接收端多出的文件也会删除，包括清空整个选中类别。

| 类别 | 实际目录（绑定用户下） |
| --- | --- |
| 聊天记录 | `chats`、`group chats`、`groups`（群聊索引） |
| 角色卡 | `characters` |
| 世界书 | `worlds` |

聊天以整个 JSONL 文件同步，同路径由来源覆盖，不合并两端消息。类别外的图片附件、预设、API 密钥、用户设置、浏览器数据、插件及插件配置不会随分类操作同步；聊天使用的角色和附件需已存在，或另行同步对应内容。

分类拉取仍通过保存核对、页面交接、停止旧实例、目录替换及新实例健康检查。会保留一次恢复副本，“恢复上一版”按最近一次实际应用的范围恢复。未受控启动时先下载并校验，候选目录只在受控继续时准备一次；本机保存改变内容后，覆盖确认会重新计算差异并要求再次确认。

## 增量与一致性

- 推送载荷只含所选类别及少量分类清单。rsync 使用 VPS 同类文件作差分基础，删除只发生在独立暂存区。VPS 校验后将选中目录合入原完整代次，保留其余文件；完整拉取仍能读取新的完整副本。
- 拉取固定一个远端代次，只请求所选文件。缺少缓存时从本机同名文件建立差分基础；其他类别不会进入候选或替换计划。
- 双方所选内容完全一致时，重新核对远端和本机后直接成功，不复制候选、不传文件、不重启。统计的零文件数据不包含 SSH 控制清单的少量开销。
- rsync 使用块级差分，结束后校验清单和全部所选文件的 SHA-256。同大小、同时间但内容不同的文件会被校验检出并定向补传。
- 分类任务绑定类别、任务 ID、数据集、代次和摘要；续传不能更改类别。分类完成记录不会覆盖完整同步的基准或缓存。
- VPS 的发布回执同时记录分类载荷摘要和合并后的完整摘要。丢失发布回执时，“核对同步结果”必须验证该任务的确切代次及分类摘要，不重新上传或应用。

VPS 仍保存完整的不可变代次。合并时使用服务器本地 reflink/复制已有副本，并执行最终校验；这部分本地磁盘处理量不代表网络上传量。实际网络统计看 `sentBytes`、`receivedBytes`，不能用快照总大小或逻辑进度代替。

## 验证边界

`tests/scoped.test.mjs` 将生产 Node 控制协议和 VPS Python 实现联跑，并使用真实 rsync daemon，通过本机进程管道替代 SSH。Windows 测试仅替换 Linux flock 和 cp，未冒充真实 Tailscale/SSH 认证或实体 Android 验收。`tests/test_vps.py` 另验证各类别组合、清空、越界拒绝、固定下载代次和发布中断恢复。

2 MiB 合成角色资源仅修改 4096 字节的用例，同时检查双向传输复用了超过 1.9 MiB，且每个方向传输量小于 64 KiB。其他用例检查选中类别的删除、其他文件摘要保持一致、无变化快速结束、原生 rsync 定向纠错、未受控继续、确认刷新及丢失提交回执后的核对。结果不是线上 VPS 或手机实测。

Windows 验证：Node 141 项通过、1 项 POSIX 跳过；Python 26 项通过、5 项 Linux 专项跳过；真实酒馆隔离环境 28 项检查及独立 rsync 回归 8 项通过。详见[验证记录](test-results/scoped-sync-windows.json)。
